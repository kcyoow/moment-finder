# 4. 질문을 어떻게 쓰면 덜 헛짚나

2026-11-12 · 판정 모델 H2O-Lightning-4B · 자료: Charades (고르는 묶음 30편, 따로 둔 묶음 12편)

## 문장만 잘 쓰면 될 줄 알았다

판정 모델은 헛짚는다. 없는 동작을 있다고 한다. 가장 먼저 떠오르는 해결책은 질문을 고치는 것이다. "분명히 보일 때만"이라고 엄하게 쓰거나, 헷갈리는 경우를 "아니오" 쪽에 적어 주면 틀린 것을 덜 잡을 것 같았다. 1장에서 Jev에 헷갈리는 동작을 적어 준 것이 통했던 기억도 있었다.

## 해 본 것

질문 틀의 변형 11개와 조합 3개를 만들었다. 엄한 말 넣기(clearly, strict), 헷갈리는 경우를 "아니오" 쪽에 적기, 판정할 문장 꼴로 바꾸기, 짧게 줄이기, 프레임 시각 빼기, 프레임 간격 넓히기 같은 것이다.

조심한 것은 하나였다. 변형이 14개면 우연히 좋아 보이는 것이 반드시 나온다. 그래서 **고르는 묶음(30편)에서 고르고, 따로 둔 묶음(12편)에서 다시 쟀다.** 어떤 것을 고를지의 규칙도 결과를 보기 전에 정했다. 재는 값은 같은 재현율에서의 정밀도, 0.5에서 자른 정밀도, 한 곳 찾기(점수가 가장 높은 한 곳이 정답 구간 안에 드는 질문의 수)다.

## 나온 것

| 바꾼 것 | 고르는 묶음 | 따로 둔 묶음 |
|---|---|---|
| 엄한 문장 (규칙대로 고른 것) | 정밀도 +0.044 | −0.013 (재현 안 됨) |
| 판정할 문장 꼴 | +0.007 | +0.064 |
| 헷갈리는 경우를 적은 설명 | 0.5 기준 정밀도 +0.021. 같은 재현율로 맞추면 −0.010 | +0.036 / +0.009 |
| 문장을 짧게 | AUC −0.009, 한 곳 찾기 −3 | −0.008, −2 |

두 묶음 모두에서 오른 변형은 하나도 없었다. 규칙대로 고른 "엄한 문장"은 고르는 묶음에서 +0.044였지만 따로 둔 묶음에서는 오히려 내려갔다. 게다가 엄한 문장은 모델을 엄하게 만들지도 않았다. 더 많이 잡았다(612 → 700곳). 헷갈리는 경우를 적은 설명은 덜 잡게는 했지만, 같은 만큼 찾도록 맞춰 놓고 보면 기준값을 올린 것과 다르지 않았다. 한 곳 찾기는 처음 쓰던 문장이 가장 높거나 같았다(90/100).

## 여기서 알게 된 것

따로 둔 묶음이 없었다면 "엄한 문장이 낫다"고 적고 넘어갔을 것이다. 문장 하나의 차이는 영상 묶음의 차이보다 작았다. 이 뒤로는 무엇을 고칠 때마다 고른 자료와 재는 자료를 나누거나, 나누지 못했으면 그렇다고 적었다.

이 모델에 "엄하게"라는 말은 판단 기준으로 읽히지 않는 것 같다. 덜 잡고 싶으면 문장이 아니라 기준값을 올리는 편이 같은 효과를 내고 더 예측하기 쉽다.

1장과 어긋나 보이는 점은 이렇게 이해했다. 1장에서는 "두 손 하트는 아니다"라는, 모델이 몰랐던 정보를 준 것이다. 여기서는 이미 준 정보를 말만 바꿨다. 통하는 것은 말투가 아니라 새 정보였다.
